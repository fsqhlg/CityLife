# 02 · 商户查询缓存（手敲清单）

> 必敲：`queryWithPassThrough`、`queryWithMutex`、`tryLock/unlock`、`update`
> 选做：`queryWithLogicalExpire`、`saveShop2Redis`

---

## 1. 必敲：`queryWithPassThrough`（缓存穿透）

**文件**：`src/main/java/com/hmdp/service/impl/ShopServiceImpl.java`
**考什么**：空值缓存、`isBlank` 与 `null` 的判断顺序、TTL 区分。

```java
private Shop queryWithPassThrough(Long id) {
    String key = CACHE_SHOP_KEY + id;

    // 1. 从 Redis 查缓存
    String shopJson = stringRedisTemplate.opsForValue().get(key);

    // 2. 命中真实数据，直接反序列化返回
    if (StrUtil.isNotBlank(shopJson)) {
        return JSONUtil.toBean(shopJson, Shop.class);
    }

    // 3. 命中空字符串：说明数据库里也没有这家店，直接返回 null，避免缓存穿透
    if (shopJson != null) {
        return null;
    }

    // 4. 未命中，查数据库
    Shop shop = getById(id);

    // 5. 数据库不存在：缓存空值，TTL 较短
    if (shop == null) {
        stringRedisTemplate.opsForValue().set(key, "", CACHE_NULL_TTL, TimeUnit.MINUTES);
        return null;
    }

    // 6. 数据库存在：写入缓存，TTL 加随机值防止缓存雪崩
    stringRedisTemplate.opsForValue().set(key, JSONUtil.toJsonStr(shop), randomTtl(), TimeUnit.MINUTES);
    return shop;
}
```

### 手敲提示

- **顺序不能反**：先 `isNotBlank`（有真实数据），再 `!= null`（空串）；
  如果先判断 `isBlank` 就返回 null，空值缓存会被当成未命中，穿透没防住。
- 空串的 TTL 用 `CACHE_NULL_TTL`（2 分钟），不要用 30 分钟。

### 验收

```
GET /shop/1        → 第一次查库，第二次走缓存
GET /shop/999999   → 返回"店铺不存在"
redis-cli get cache:shop:999999   → ""
redis-cli ttl cache:shop:999999   → 约 120
再查一次 999999                    → 0 次 SQL
```

## 2. 必敲：`queryWithMutex`（缓存击穿·互斥锁）

**文件**：`ShopServiceImpl`
**考什么**：`SET NX EX`、双重检查、锁的释放位置、重试。

```java
private Shop queryWithMutex(Long id) {
    String key = CACHE_SHOP_KEY + id;

    // 1. 查缓存
    String shopJson = stringRedisTemplate.opsForValue().get(key);
    if (StrUtil.isNotBlank(shopJson)) {
        return JSONUtil.toBean(shopJson, Shop.class);
    }
    if (shopJson != null) {
        return null;
    }

    // 2. 未命中，尝试获取互斥锁
    String lockKey = LOCK_SHOP_KEY + id;
    Shop shop;
    if (!tryLock(lockKey)) {
        // 没抢到锁：稍等后重试
        try {
            Thread.sleep(50);
        } catch (InterruptedException e) {
            Thread.currentThread().interrupt();
            throw new RuntimeException("查询店铺缓存被中断", e);
        }
        return queryWithMutex(id);
    }

    // 3. 抢到锁后必须释放：只有拿到锁的线程才进 finally
    try {
        // 3.1 双重检查：可能在等锁期间，别的线程已经把缓存建好了
        shopJson = stringRedisTemplate.opsForValue().get(key);
        if (StrUtil.isNotBlank(shopJson)) {
            return JSONUtil.toBean(shopJson, Shop.class);
        }

        // 3.2 查数据库
        shop = getById(id);

        // 3.3 不存在：缓存空值
        if (shop == null) {
            stringRedisTemplate.opsForValue().set(key, "", CACHE_NULL_TTL, TimeUnit.MINUTES);
            return null;
        }

        // 3.4 存在：写回缓存
        stringRedisTemplate.opsForValue().set(key, JSONUtil.toJsonStr(shop), randomTtl(), TimeUnit.MINUTES);
    } finally {
        // 4. 释放锁
        unlock(lockKey);
    }
    return shop;
}
```

### 手敲提示

- **最关键**：`if (!tryLock(...))` 在 `try` 外面。如果写成 `try { if (!tryLock) ... } finally { unlock }`，没抢到锁的线程会把别人的锁删掉。
- 双重检查必须做，否则等锁期间缓存已建好，白查一次库。
- 递归重试最多几十层，演示够用；生产建议循环 + 限次。

### 验收

```
redis-cli del cache:shop:2
用 10 个并发打 /shop/2
看日志：只出现 1 条 "Preparing: SELECT ... tb_shop"
```

## 3. 必敲：`tryLock` / `unlock` / `randomTtl`

**文件**：`ShopServiceImpl`

```java
private boolean tryLock(String key) {
    Boolean flag = stringRedisTemplate.opsForValue()
            .setIfAbsent(key, "1", LOCK_SHOP_TTL, TimeUnit.SECONDS);
    return BooleanUtil.isTrue(flag);
}

private void unlock(String key) {
    stringRedisTemplate.delete(key);
}

private long randomTtl() {
    return CACHE_SHOP_TTL + RandomUtil.randomInt(0, 10);
}
```

**注意**：`setIfAbsent(key, value, timeout, unit)` 才是 `SET NX EX`；两参数的版本没有过期时间，会死锁。

## 4. 必敲：`update`（缓存更新策略）

**文件**：`ShopServiceImpl`

```java
@Override
@Transactional
public Result update(Shop shop) {
    Long id = shop.getId();
    if (id == null) {
        return Result.fail("店铺id不能为空");
    }

    // 1. 先更新数据库
    updateById(shop);

    // 2. 再删除缓存
    stringRedisTemplate.delete(CACHE_SHOP_KEY + id);

    return Result.ok();
}
```

**注意**：是「删缓存」不是「更新缓存」；顺序是「先更库、后删缓存」。

### 验收

```
PUT /shop {"id":1,"sold":9999}
redis-cli exists cache:shop:1   → 0
GET /shop/1                     → sold 是 9999
```

## 5. 选做：`queryWithLogicalExpire` + `saveShop2Redis`（逻辑过期）

**文件**：`ShopServiceImpl`

```java
private Shop queryWithLogicalExpire(Long id) {
    String key = CACHE_SHOP_KEY + id;

    // 1. 查缓存，未命中直接返回 null（逻辑过期只服务已预热的数据）
    String shopJson = stringRedisTemplate.opsForValue().get(key);
    if (StrUtil.isBlank(shopJson)) {
        return null;
    }

    // 2. 反序列化出数据和逻辑过期时间
    RedisData redisData = JSONUtil.toBean(shopJson, RedisData.class);
    Shop shop = JSONUtil.toBean((JSONObject) redisData.getData(), Shop.class);
    LocalDateTime expireTime = redisData.getExpireTime();

    // 3. 未过期：直接返回
    if (expireTime.isAfter(LocalDateTime.now())) {
        return shop;
    }

    // 4. 已过期：抢锁，异步重建，当前请求仍返回旧数据
    String lockKey = LOCK_SHOP_KEY + id;
    if (tryLock(lockKey)) {
        CACHE_REBUILD_EXECUTOR.submit(() -> {
            try {
                saveShop2Redis(id, 20L);
            } catch (Exception e) {
                log.error("重建店铺缓存失败，shopId={}", id, e);
            } finally {
                unlock(lockKey);
            }
        });
    }

    // 5. 没抢到锁也没关系，直接返回旧数据
    return shop;
}
```

```java
@Override
public void saveShop2Redis(Long id, Long expireSeconds) {
    Shop shop = getById(id);
    if (shop == null) {
        return;
    }

    RedisData redisData = new RedisData();
    redisData.setData(shop);
    redisData.setExpireTime(LocalDateTime.now().plusSeconds(expireSeconds));

    // 注意：这里不设置 TTL，逻辑过期由 expireTime 控制
    stringRedisTemplate.opsForValue().set(CACHE_SHOP_KEY + id, JSONUtil.toJsonStr(redisData));
}
```

**注意**：

- 逻辑过期的 key **不设 TTL**，否则物理过期后直接查不到；
- 必须先预热（`saveShop2Redis`），否则所有请求返回 null；
- 逻辑过期格式和互斥锁格式共用同一个 key，**不要混用**。

### 验收

```
先跑测试 testSaveShop2Redis 预热 id=1（10 秒后过期）
把 queryById 里的 queryWithMutex 换成 queryWithLogicalExpire
GET /shop/1           → 正常返回
等 10 秒再 GET        → 仍返回旧数据，后台线程重建
redis-cli get cache:shop:1 → expireTime 变新
```

## 6. 看懂即可：`queryById` 的开关

```java
@Override
public Result queryById(Long id) {
    // 方案一：queryWithPassThrough(id);
    // 方案二：queryWithMutex(id);
    // 方案三：queryWithLogicalExpire(id);
    Shop shop = queryWithMutex(id);

    if (shop == null) {
        return Result.fail("店铺不存在！");
    }
    return Result.ok(shop);
}
```
